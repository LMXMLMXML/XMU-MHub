## 这个软件是什么

一个把**厦门大学全校网站、系统与小程序按「校区 / 对象 / 用途」统一收口**的 Windows 桌面软件，
同一份前端还能直接当公网网页 / 手机 App（PWA）用。

> 📁 想自己从源码跑 / 重新打包？看 [REPO_NOTES.md](REPO_NOTES.md)
> —— 说明仓库里有什么、没有什么（exe 走 Release 分发，不进版本控制）、以及怎么补回来。

## 解决什么问题

厦大的网上入口极度分散：官网、信息门户、企业微信、几十个业务系统、十几个小程序，
再加上各学院、各校区的独立站点——**新生和老师经常不知道该去哪儿办事**：

- 想查成绩 → 要区分教务服务平台、智慧教务小程序、研究生教育公众号；
- 想报修 → 要区分「厦大后勤」公众号和智慧后勤网页；
- 想预约进校 → 得知道「厦门大学访客预约系统」公众号 +「参观厦大」小程序；
- 翔安校区的同学还要再筛一遍哪些是本校区的。

本软件把这些入口一次性收进 320 条结构化目录，任何入口都能在 **3 秒内**按校区/身份/用途定位，
或者直接用一句大白话让 AI 帮你找。

## 核心功能

| 功能 | 说明 |
|---|---|
| **首页落地页** | 打开软件先看到首页而非几百张卡片：欢迎区（校徽 + 数据徽章）→ **10 个常用场景**（查成绩 / 宿舍报修 / 进校预约 / 场馆预约 / 报销 …一点直接搜）→ **12 个精选入口** → **5 张维度卡**（校区/对象/用途/端/形态，点标签直接筛）→ 收藏 / 最近打开 / 搜索记录 → 「浏览全部 320 个入口」 |
| **四维分类筛选** | 按 **校区**（通用/思明/翔安/漳州/马来西亚）、**对象**（全体/本科生/研究生/教师/校友/访客）、**用途**（学习/科研/办事/生活/资讯/出行）、**端**（手机端/电脑端/手机+电脑/线下）任意交叉筛选；选校区时自动包含"全校通用"条目，并把该校区专属条目排在前面 |
| **手机端 / 电脑端区分** | 每条都标注使用端：小程序·公众号·APP 归为**手机端**，网页系统归为**电脑端**，企业微信等归为**双端**，馆内触摸屏等归为**线下**（分布：电脑端 301、手机端 35、双端 4、线下 2） |
| **逐条简介** | **320 条全部有中文简介**，优先采用总集原文，其次人工撰写（约 60 条高频入口），其余按单位类型生成，卡片与详情页都能直接读懂这条是干什么的 |
| **口语化搜索** | 中英混合分词（单字 + 2-gram），内置校园同义词库：「饭卡」→数字校园卡、「报修」→后勤、「查重」→图书馆、「报销」→财务处；另有**意图扩展**——说「漏水 / 坏了 / 堵了」会自动补上「报修、维修」，避免字面命中「宿舍水控」这类近形词 |
| **AI 找入口（不需要 Key）** | 用自然语言提问。默认走**内置本地检索**（财务处、后勤、教务等入口照样答全）；想让它在候选里再挑一遍并说明理由，就在界面 ⚙ 里**下载一个本机模型**（免费、断网可用、一次下载长期有效） |
| **一键直达** | 网站一律用**系统浏览器**打开（软件内不再内嵌网页，原因见「踩过的坑 6」），并且**自动把浏览器窗口提到软件前面**（`focus_browser`：开之前先拍窗口快照，开完认出新窗口或原窗口再 `SetForegroundWindow`）；小程序/公众号一键**复制名称**并提示微信搜索（小程序无法从系统外部直接唤起） |
| **手机 / PWA 也能用** | 同一份前端，不需要 Python 也不需要重写：`python tools/build_mobile.py` 生成 `dist-mobile/`（936 KB），丢到任意静态空间，手机浏览器打开即用，加到主屏就是个 App（可离线）。详见「手机端 / PWA」一节 |
| **收藏 / 最近打开 / 搜索记录** | 三者都本地持久化（`data/userdata.json`），重启后保留；搜索记录最多 12 条，点搜索框即出现、可一键清空 |
| **说明类页面降权** | 列表仍然完整收录 320 条（含学院官网、公告、使用指南等），但检索时"机构门户 / 说明书"类条目统一 **−2.0 分**（`role=info`），保证「游泳」「报修」这类查询不会先弹出无关公告 |
| **刷新 / 断线都不白屏** | 当前视图（首页/列表 + 关键词 + 各维筛选）写进地址栏 hash，**刷新后回到原样**（不会出现"框里有词、列表却是全部"）；后端断开时明确提示「没有连上本地服务 + 重试」，不再伪装成"没有匹配的入口"；窗口重新激活会探活并显示断线横幅 |
| **空结果能自救** | 真的没结果时给出原因（"这些条件叠加后没有结果；去掉筛选后还有 N 条"）+ 三个按钮：放宽筛选 / 让 AI 帮我找 / 清空条件，并给出几个更可能命中的说法 |
| **单实例复用** | 已有实例在运行时，再双击 exe 会**直接复用**它而不是再开一个端口（`--new` 可强制新实例），避免"两个实例、其中一个退出后旧窗口刷新什么都没有" |
| **详情与溯源** | 每条都标注所属板块、主管单位、收录来源（《网址总集》/《小程序总集》的哪一节），可核对 |
| **易混淆提示** | 专门收录"容易被当成小程序、其实是网页/公众号"的入口（如图书馆座位预约是公众号、篮球场预约在企业微信里） |

## 界面设计（LOGO 取色 + OH 配色）

设计语言参考 Linear / Raycast / Vercel 这类高评价开发工具：**1px 细边框、克制的单一强调色、等宽数字、命令面板优先、浅深双主题**。

### 配色：全部从官方素材里取出来

配色不是凭感觉调的，而是用 `tools/extract_palette.py`（Pillow 量化）从官方素材里提取：

| 素材 | 取色结果 | 用途 |
|---|---|---|
| 厦大官网 LOGO | **#0D2F6E**（占 80.5%） | 品牌主色 `--brand` |
| 厦门大学校徽 | #273D6B | 品牌深色层 |
| 信息学院院徽 | **#134C92 → #0C81BD → #8AB8D7** | 强调色 `--accent: #0C81BD` |
| OpenHarmony 标识 | **#45ABDC**（蓝）+ **#75C754**（绿） | 强调亮色与 OH 绿 `--oh-green` |

三套配色天然同源（都是蓝），所以放在一起不冲突：藏青做品牌、信息学院蓝做交互强调、OH 绿做成功态与手机端标识。顶栏底部一条 `藏青 → 信息学院蓝 → OH 绿` 的渐变线就是这个来源。

端色也来自这套色：电脑端=藏青、手机端=信息学院蓝、双端=OH 绿、线下=灰。

### 踩过的坑：抽屉关不掉

早期版本 `openDrawer()` 生成的 HTML 外层套了一个 `<div class="drawer">`，而 `.drawer` 正是全屏遮罩样式
（`position:fixed; inset:0; z-index:50`）——于是抽屉内部又铺了一层全屏遮罩，把外层的 ✕ 和背景遮罩**盖住**了，
只有 Esc 能关。

为什么自动化测试没发现：jsdom 没有布局引擎，测试用 `dispatchEvent` **直接对 ✕ 元素派发点击**，绕过了命中测试，
所以"能点到"这件事根本没被验证。

修复与加固：
1. 内容层改名 `.drawer-inner`，遮罩选择器收紧为 `#drawer`；
2. `#palette`、`#aiPanel` 一并改用 ID 选择器；
3. 新增两条回归断言：**面板内 `position:fixed` 后代数必须为 0**、**内容里不得嵌套遮罩 class**；
4. `tools/ui_check.py` 增加静态检查：裸类选择器必须为 0、JS 生成同名 class 的必须为 0。

### 踩过的坑 2：测试打到了旧实例

调试时反复出现"明明改了数据，测试结果没变"。原因：旧的后端实例（有时是之前启动的打包版）
仍占着 8765，新实例按逻辑顺延到 8766，而测试脚本硬编码 8765 ——于是**测试一直在读旧数据**，
一度让我误判修复无效。

修复与加固：
1. 程序启动时把**实际监听端口写入** `data/_runtime_port.txt`；
2. 所有测试脚本改为读该文件（读不到才回退 8765）；
3. 排查脚本 `Get-Process | Where-Object { $_.ProcessName -match '厦大统一门户|python' }` 已写进排查习惯。

### 踩过的坑 3：AI 会"拒答"和"挑偏"

免费模型在几个相近候选之间偶尔会答"没有匹配到"，或把"研究生查成绩"推荐成"体测预约与成绩查询"。
两者都是模型问题，不是数据问题，但会直接毁掉体验。

修复与加固：
1. **拒答兜底**：模型回"没有匹配到/未找到"但候选非空时，改用本地检索结果作答，避免
   回答文案与下方推荐按钮自相矛盾；
2. **把推断结果写进提示**：系统已推断出"用户身份=研究生、用途=学习"，就把这条一起发给模型，
   让它按身份筛，而不是只看名称里有没有"成绩"两个字；
3. 提示词明确"候选已预筛过，通常都有答案，不要轻易说没有匹配到"。

### 踩过的坑 4："刷新一下就什么都没有了"

用户反馈"经常出现没有匹配的入口的界面"。用真实前端跑了 30 句自然说法 + 约 200 组
"关键词 × 单个筛选"的组合，**落空 0 组**——说明问题不在检索，而在页面加载：

- 打包版默认用 Edge 的 `--app` 打开 `http://127.0.0.1:8765/index.html`，端口是运行时选的；
  而开发/试用期间软件被反复重启，**旧窗口还开着、它对应的那个实例已经退出**。
- 这时刷新页面：`/api/catalog` 请求失败 → `boot()` 直接抛异常 → 列表为空、骨架屏不消失，
  页面看起来就是"没有匹配的入口 / 一片空白"。
- 叠加因素：浏览器会把上次的输入"复原"到搜索框里，如果 `state.query` 没同步，就会出现
  "框里有'报修'、列表却是全部条目"的错位。

修复：
1. **启动重试**：`/api/catalog` 失败退避重试 4 次（约 4 秒，覆盖单文件自解压那几秒）；
2. **区分两种"空"**：目录没加载 → 「没有连上本地服务 + 重试」（并说明原因）；
   真的搜不到 → 「没有匹配的入口」+ 放宽筛选 / 让 AI 找 / 清空条件；
3. **断线探活**：窗口重新激活时打一次 `/api/ping`，失败就显示顶部横幅；
4. **地址栏存状态**：视图+关键词+筛选写进 hash，刷新回到原样，搜索框与 `state.query` 强制对齐；
5. **单实例复用**：启动时先探端口文件里的实例，活着就直接开它，不再起第二个端口。

### 踩过的坑 5：分类"牛头不对马嘴"（用户反馈）

反馈原话：**"分类有很大问题，牛头不对马嘴，还有很多错乱的页面"**。查下去发现是三个叠加的坑：

1. **关键词袋套一切**：`用途/对象` 是靠一大袋词往"名称+说明"上匹配得来的，
   袋子里有"学院""中心""参观""组织"这类大词，于是
   「网上展馆 → 用途=出行」（因为说明里有"可线上参观"）、
   「校园地图 → 对象=教师」「所有部处 → 用途=办事」。
2. **模板凑说明**：一条兜底模板 `{name}：部门职责、办事流程、表格下载与通知公告。`
   被套在 45 个单位上——宣传部的"办事流程"、学报编辑部的"表格下载"、实验动物中心的"通知公告"，
   全是废话；还有两条说明直接拼进了章节号（"厦门大学7.6 地球科学与技术学部相关入口""厦门大学二"）。
3. **合并顺序错了**：判重时先算好分类、再把重复行 `update` 进来，重复行把干净的标签
   覆盖回脏标签（校园地图、网上展馆就是这么坏的）；而且判重只比完整网址字符串，
   `http://` 与 `https://` 被当成两个站点，"实验动物中心"于是出现两条。

修法（都已落地并有闸门守住）：

### 踩过的坑 6：软件内打开——试过、修过，最后按反馈去掉

起因是你在需求里问的"可以做到让网址在软件内打开吗"。做完之后先用数据摸了一次底：

| 实测（271 个可达网址） | 数量 | 占比 |
|---|---|---|
| 允许被 iframe 直接嵌入（无 X-Frame-Options / CSP 限制） | 55 | 20% |
| **禁止被嵌套**（多为 `X-Frame-Options: SAMEORIGIN`），只能靠本地代理转发 | 214 | 78% |
| 打不开 | 2 | 1% |

自己写代理转发这条路，前后踩了三层坑：

1. **相对路径按"跳转前"的地址算**。`jw.xmu.edu.cn` 会 302 到 `/new/index.html`，
   而页内写的是 `resources/js/jquery.i18n.js` 这类相对路径；用原始请求地址当基准就解析成
   `/resources/js/...` → 404。整页 49 个引用里 **41 个取不到**（jQuery 插件、皮肤 CSS、logo 全挂），
   脚本一抛错页面就永远停在"请耐心等待……"。改法：用 `resp.geturl()`（跳转后的真实地址）当基准，41 → 8。
2. **抓取失败时把 HTML 错误页当 JS 发**，浏览器按 `application/javascript` 解析直接语法错误、整页崩。
   改法：按扩展名回"类型正确、内容为空"的响应。
3. **页面里用相对地址发的接口请求落到了本机**，404。改法：按 Referer 记的原站地址补全再转发。

登录是另一层：办事大厅的登录按钮走的是**写死在 `school.json` 里的绝对地址**
（`window.open("https://ids.xmu.edu.cn/authserver/index.do?service=http://jw.xmu.edu.cn", "_self")`），
改写不到；内嵌窗口于是直接跳到真实站点——统一身份认证恰好允许被嵌套，登录看着正常，
但成功后它把窗口重定向回 `jw.xmu.edu.cn`，那个站是 `SAMEORIGIN`，**浏览器直接拒绝渲染**。
（顺带还查到一个真 bug：`checkNeedCaptcha.htl` 的响应被追加了底部提示条，
`{"isNeed":false}<div …` 让 jQuery 解析 JSON 直接抛错。）

**结论（2026-09-25，按反馈"不用在软件内打开了"）**：这条路成本高，而且天花板是站点自己的策略——
`X-Frame-Options`、`SameSite`、扫码登录、企业微信授权都没法在转发里完整还原。所以**整块去掉**：

- 删掉查看器窗口、卡片上的「软件内打开 / 浏览器打开」切换、`openMode` 偏好
- 删掉 `/api/embed`、`/api/proxy`、`/api/proxy/clear` 与整套代理代码（`app.py` 1837 → 1333 行）
- 点条目一律 `webbrowser.open` 交给系统浏览器：该登录就登录，该用哪个内核就用哪个内核

顺手留下两个与浏览方式无关的修复：

| 修复 | 说明 |
|---|---|
| `POST /api/profile` 那行 `if` 被吃进上一行注释里 | 它后面所有 POST 路由（本机模型、下载、启动服务）全被一个无条件 `return` 顶掉，拆行修好 |
| `/api/open` 的目录校验改用 `noscheme()` | 目录里收的是 `https://jwc.xmu.edu.cn`，总集里有些行写的是 `http://`；不抹平协议会被判成"目录外地址"拒绝打开 |

### 点开网址后，让浏览器窗口压在软件上面

软件自己就是一个 Edge 应用模式窗口，点条目后新开的浏览器窗口经常被它挡在后面（Windows 默认不让后台进程抢前台，
只在任务栏闪一下）。处理办法（`app.py` 的 `open_in_browser` / `focus_browser` / `raise_window`）：

1. **打开之前**先 `EnumWindows` 拍一张"当前有哪些浏览器窗口"的快照，并按进程名过滤
   （chrome / msedge / firefox / brave / 360 / QQ 浏览器 …），同时**排除软件自己的窗口**
   （标题以「厦大统一门户」开头）——否则"提到前面"的会变成软件自己；
2. `webbrowser.open(url)` 交系统默认浏览器打开（用你自己的浏览器配置，登录状态都在）；
3. 后台线程最多等 8 秒，按三种情况处理：
   浏览器已经在前台 → **什么都不做**（不去动你正在看的窗口）；冒出**新窗口**（首次启动/新开窗口）→ 提新的那个；
   只是**原窗口加了个标签** → 等 1.5 秒确认它没自己跳上来，再提原窗口；
4. 提窗口先直接 `SetForegroundWindow`；被前台锁挡住时才补一次 ALT 轻敲再试
   （常规绕锁做法，用户看不到界面变化，也不会平白往系统里塞按键）。

自测（默认不打扰你正在用的窗口）：

```
python tools/check_browser_focus.py            # 枚举 / 排除自身 / 异常输入 / 三种判断 / 快照顺序 / HTTP 路由
python tools/check_browser_focus.py --open     # 真开一个标签页做端到端（会在浏览器里多一个标签）
```

最近一次实机结果：识别到 1 个浏览器窗口、软件窗口被正确排除、`raise_window(0/12345/-1)` 都安全返回 False、
三种判断分别得到 `提 0 次 / 提 [222] / 提 [111]`、快照顺序为 `snapshot → open → focus`；
走真实 HTTP 路由 `POST /api/open`：收录条目「厦门大学主页」→ 事件 `['snapshot', ('open', 'https://www.xmu.edu.cn'), 'focus']`，
目录外网址 → HTTP 400 且**一次浏览器都没开**。
> 说明：窗口枚举与全部判断逻辑都在你机器上实测过；**"肉眼看到浏览器跳到最前"这一步本机沙箱起不了 Edge，
> 需要你自己点一次确认**。如果哪次没压上来，把 `python tools/check_browser_focus.py --open` 的输出发我。

## 手机端 / PWA（同一份前端，静态托管就能用）

### 为什么不用重写

量过一遍代码才发现，这个软件**本来就该是纯前端的**：搜索、筛选、排序、同义词扩展全在
`web/app.js` 里（`tokenize` + `scoreItem` + `visibleItems`，约 130 行），整个前端对后端的
数据依赖只有**一处**——`boot()` 里的 `fetch('/api/catalog')`。后端那 1400 多行 Python 存在的
理由只有三个：桌面窗口、调系统浏览器、把收藏写进本地文件。这三件事手机浏览器自己就会。

所以做法是**渐进增强**，而不是另写一套：

| 原来 | 手机上（静态托管）怎么办 |
|---|---|
| `fetch('/api/catalog')` | 读同目录的 `portal.json`（328 KB）。先试后端，拿不到才回落——桌面版行为不变 |
| `fetch('/api/userdata')`（收藏/最近/搜索记录/身份） | 换 `localStorage` |
| `POST /api/open`（后端调 `webbrowser.open`） | 换 `window.open(url)` |
| `GET /api/search` + `POST /api/ask`（AI 问答） | 换浏览器里直接算：`localSearch` / `localAnswer`，与后端同一套打分和同义词 |
| `facets`（统计与筛选项计数） | `portal.json` 里只有 items（后端是现算的），静态版用 `computeFacets()` 自己数一遍，口径与 `Catalog.facets()` 一致 |
| `/api/ai/*`（下载本机模型） | 手机上跑不了几 GB 的模型，静态模式下按钮直接不出现，问答就是本地检索 |

判断方式：开机先试 `/api/catalog`，拿不到就退到 `portal.json` 并把 `BACKEND` 置 false；
`api()` 只有在"连不上"时才切换，业务错误（比如 400 拒绝目录外地址）仍照原样返回。

### 怎么用

```
python tools/build_mobile.py        # 生成 dist-mobile/（24 个文件，936 KB，含 portal.json）
python tools/preview_mobile.py      # 本机起静态服务并打印局域网地址，手机连同一 WiFi 打开
```

正式托管：把 `dist-mobile/` 整个目录传到任意静态空间即可（校内服务器 / GitHub Pages / 对象存储 / nginx）。
**建议用 https**——PWA 只有在 https（或 localhost）下才能"添加到主屏幕"，http 也能正常用，只是装不了。

### 手机上的改动

- **布局**：`styles.css` 里新增 `@media (max-width: 820px)`：卡片单列、触控目标 ≥42px、
  顶栏收成两行（品牌 + 操作 / 搜索占满），**左侧栏变成抽屉**（顶栏 ☰ 拉出、点遮罩或选中筛选项自动收起）
- **PWA**：`manifest.json`（名称/图标/主题色/standalone）+ `sw.js`
  （外壳缓存优先、`portal.json` 网络优先、`/api/*` 一概不碰）
  > 文件必须叫 `.json` 不能叫 `.webmanifest`：Netlify / Cloudflare / GitHub Pages 都不认识
  > 后者，会回 `application/octet-stream`，浏览器据此判定 manifest 无效、**"添加到主屏幕"直接不可用**。
  > 另外 Chrome 判定"可安装"要求图标里**至少有 192px 和 512px** 两个尺寸（`tools/make_pwa_icons.py` 生成）。
- **Service Worker 只在非本机地址注册**：桌面版跑在 `127.0.0.1` 上，注册了会把界面缓存住，
  导致 exe 更新后窗口刷新还是旧界面——所以本机地址一律不注册

### 怎么才算「像 App 一样打开」

装到主屏之后是这个体验：**主屏上一个图标，点开全屏、没有地址栏**，长按图标有
「查成绩 / 宿舍报修 / 场馆预约」三个快捷入口，**断网也能翻目录**（外壳和目录数据都缓存了）。

前提只有一条：**必须是 https**（浏览器硬性要求；Service Worker 也只在 https / localhost 下工作）。
局域网 http 能看能用，但装不了。三条路：

| 路线 | 怎么做 | 适合 |
|---|---|---|
| **A. 传到 https 静态空间**（推荐） | 把 `dist-mobile/` 整个目录拖上去：GitHub Pages / Cloudflare Pages（支持拖拽上传）/ 对象存储 / 校内服务器 + 证书。**传一次，所有人下次打开就是新的** | 正式用 |
| **B. 临时演示** | `cloudflared tunnel --url http://localhost:8080` 或 `npx localtunnel --port 8080`，拿到一个 `https://…` 地址，手机打开即可装 | 答辩 / 给人试 |
| **C. 想要真正的原生 App** | 用 Capacitor 把 `dist-mobile/` 套一层壳打成 APK（要 Android SDK + Java）；或者做微信小程序 | 要上架 / 要微信生态 |

`python tools/preview_mobile.py` 启动时会直接把这些命令和"有没有装工具"打印出来。

**微信里的现实**：同学们多半是在微信里点开链接，而**微信内置浏览器不支持装 PWA**。
应用里已经识别这种情况——在微信里点「装到主屏」，会先告诉你「右上角 ⋯ → 在浏览器中打开」。
真要彻底解决，只有做微信小程序（小程序本身也不用安装，还能一键跳转其他小程序）。

### 应用里做的安装引导

顶栏加了「📲 装到主屏」按钮（已装到主屏、或桌面版 127.0.0.1 上会自动隐藏），点开按机型给不同的话：

|---|---|
| 安卓 Chrome / Edge（浏览器抛出安装事件） | 一个**「一键添加」**按钮，点了直接调起系统安装 |

`display_override` 保证以 standalone 全屏打开，manifest 里带了三个 `shortcuts`。

### 硬限制（先说清）

1. **iOS 的 PWA 存储可能被系统清理**（长期不用会被回收），收藏别当成唯一凭据
2. **手机跑不了本机大模型**：手机上的问答就是本地检索（不联网、不要 Key），要更强的 AI 得接云端
3. **小程序条目在手机网页里仍然是"复制名称"**：只有真的做成微信小程序才能一键跳转
4. 静态版的收藏/最近/身份存在浏览器里，**换浏览器或清缓存就没了**（不像桌面版存在 `userdata.json`）

## 发到公网（一个网址，打开就是这套软件）

`dist-mobile/` 就是**这套软件的 1:1 网页版**——同一份前端代码、同一份 320 条数据、同一套搜索与本地检索，
差别只是没有桌面窗口和本机后端。把它传上任意静态托管，就得到一个公开网址：

```
python tools/build_mobile.py                      # 产出 dist-mobile/（约 1 MB，含 portal.json）
python tools/deploy_check.py https://你的网址/     # 上线后一条命令验收
```

三条路线（逐步照做见 **[DEPLOY.md](DEPLOY.md)**）：

| 路线 | 操作 | 网址长什么样 |
|---|---|---|
| **Cloudflare Pages**（推荐） | 注册 → Workers & Pages → Create → Pages → Upload assets → 把 `dist-mobile` 文件夹整个拖进去 | `https://xmu-hub.pages.dev` |
| **Netlify Drop**（最省事） | 打开 <https://app.netlify.com/drop>，把文件夹拖进去 | `https://随机名.netlify.app` |
| **GitHub Pages** | `dist-mobile` 里 `git init` → 推到仓库 → Settings → Pages 选 main/root | `https://用户名.github.io/仓库名/` |

`build_mobile.py` 已经把托管平台要用的零碎文件一起写好了：`_headers`（缓存策略：
`portal.json` 不缓存、`assets/*` 缓存一周）、`robots.txt`、`.nojekyll`（GitHub Pages 不走 Jekyll）。
**整个目录原样上传，不用改任何文件。**

部署后你会得到：

- 手机浏览器打开 → **添加到主屏幕**，点图标全屏打开、断网也能翻目录（需 https）
- 发到微信群/QQ 群 → 显示 `share-card.png` 那张卡片（`og:title` / `og:description` / `og:image`，
  由 `tools/make_share_card.py` 生成，600×480）
- 更新数据只要 `build_data.py` → `build_mobile.py` → 重新部署一次，**所有人下次打开就是新的**
  （桌面版 exe 则要重新打包分发——这是网页版最省事的地方）
- 页面左侧栏写明了「本站是学生作品、不是厦门大学官方产品，数据整理自各单位官网公开信息」；
  要挂到学校名下需要走学校审批

> 只想先给人看一眼、不想注册托管：`python tools/preview_mobile.py 8080` 起本机服务，
> 另开窗口 `cloudflared tunnel --url http://localhost:8080`（或 `npx localtunnel --port 8080`）
> 拿一个临时 https 地址，电脑关了就失效。

### 电脑端首页会把手机端网址显示出来

部署完拿到公网地址后，桌面版首页底部会多出一块「📱 手机上也能用」：

- 把网址本身显示出来（等宽字体，长网址会换行），配一句说明：**同一份数据**、手机浏览器直接打开、
  在浏览器菜单里「添加到主屏幕」之后图标点开就是全屏、断网也能翻看过的入口
- **复制网址**：一键复制，直接发到微信 / QQ 给自己或同学
- **在浏览器打开**：交给本地后端调系统浏览器（窗口会提到软件前面）
- 只在桌面版出现：手机上本来就在用这个网址，静态托管版（公网 / PWA）没有后端、拿不到这个地址，
  两种情况都不显示，避免废话

网址只写在一个地方——`app.py` 顶部的 `MOBILE_SITE`。换部署地址只改这一行，或者启动时临时覆盖：

```
python app.py --mobile-url https://你的新地址/      # 不改代码也能换
```

前端不写死网址：开机时从 `/api/ping` 取（`{"ok":true,"items":320,"mobile":"https://…"}`）。
`/api/open` 的白名单只额外放行**这一个**地址，其余照样拒绝——本地服务不会被当成打开任意网址的跳板
（收录目录 320 条仍然走原来的白名单）。

自检：

```
python tools/check_mobile_url.py --live      # 后端：ping 给没给 / open 放不放行 / 白名单有没有被放宽 + 联网确认
cd .devtools && node mobile_url_test.mjs     # 前端：桌面显示、手机不显示、静态版不显示、复制与打开两个按钮
```

### 踩过的坑 7：把「精选」缩到 7 个，顺手把搜索结果砍了 25%

用户要求首页精选只留 7 个入口。改完 `FEATURED_URLS` 一看回归数据，**搜索条数集体缩水**：

| 查询 | 改之前 | 只改 featured 之后 |
|---|---|---|
| 报销 | 62 条 | **47 条** |
| 成绩 | 89 条 | **73 条** |
| 报修 | 63 条 | **48 条** |
| 游泳 | 31 条（★XMUSPORTS 第一） | **13 条**（XMUSPORTS 掉到第二） |

原因：`featured` 一直**同时**担着两件事——首页展示，以及检索打分里的 **+1.2 常用加权**。
19 条被取消精选后集体掉 1.2 分，而列表渲染有一条 `if (terms.length && s <= 0) continue`，
分数掉到 0 以下的条目就被**整个过滤掉**了。

改法：**把两件事拆开**。

- `featured` = 只给首页和命令面板的空查询列表用（现在是 7 个）
- 新增 `hot` = 只做检索加权 +1.2，名单保持原来的 26 条不变（`HOT_URLS` / `HOT_NAMES`）
- `app.py` 的 `score_item`/`search` 与 `web/app.js` 的 `scoreItem`/两处排序，全部从 `featured` 换成 `hot`

拆完四条查询的条数与排序**逐条回到改前水平**（62 / 89 / 63 / 31，XMUSPORTS 重新第一）。
教训：**一个字段别同时管"展示"和"排序"**——改展示的时候排序会跟着动，而回归数据不一定马上看得出来。

```bat
python -m pip install --target "%CD%\.buildtools" pyinstaller

:: 绿色版（onedir，推荐交付）
python -m PyInstaller --noconfirm --clean --windowed --onedir ^

:: 单文件版（体积小，但要自解压到临时目录，杀毒误报率更高）

> 用 `$PWD` / `%CD%` 而不是写死的绝对路径：这个仓库以前在 `D:\AI\xmu_hub\`，
> 换到 `OH二面\vibe coding\` 之后，写死的路径整段失效。

> 打包前记得先关掉正在运行的 exe，否则会 `PermissionError: [WinError 5]`（`dist` 里的文件被占用，无法覆盖）。
> **重新打包会整目录重建 `dist\厦大统一门户-绿色版\`**，而这个目录里的 `data\` 正是绿色版的用户数据
> （收藏 / 最近打开 / 搜索记录）——绿色版用户重新打包前请先备份 `dist\厦大统一门户-绿色版\data\userdata.json`；

> **自己打包只是为了改动后验证**。对外发布不用手动打——推一个 `v*` tag，

## AI 引擎说明

**AI 问答默认不需要任何 Key**：没有配置任何大模型 Key 时，问答直接走**内置本地检索**
（问题 → 同义词/意图扩展 → 打分排序 → 给出财务处、后勤、教务等入口），
面板头部会显示「本地检索」并提示可以填 Key。**已移除之前那个免密钥的公共免费接口**
（Pollinations 免费档 2026-09 起改为返回"额度不足"，留着只会误导）。

### AI 设置：只配本机模型（不需要 Key）

AI 面板右上角 **⚙** 打开「本机 AI 设置」，里面只有一件事：把模型装到本机。

- **检测** 本机 Ollama（装没装、跑没跑、有哪些模型）
- **一键下载**：没装 → 下载官方安装包（约 700 MB，**只下载不静默安装**）；装了没模型 → 三个推荐模型各带「下载」按钮
- **进度条**：实时显示 `下载中 85%｜8.1 MB / 9.5 MB｜downloading`，下完**自动切换**过去
- **界面里没有任何填 API Key 的选项**（按反馈去掉）。密钥不落盘：`data/userdata.json` 里只有收藏 / 最近打开 / 搜索记录 / 本机模型名
- 没装本机模型时，问答直接走**内置本地检索**（财务处、后勤、教务等入口照样能答）
- 进阶用户仍可用环境变量接入云端大模型（`DEEPSEEK_API_KEY` 等，见下表），程序会自动优先使用

```
（有环境变量时）DeepSeek → 智谱 GLM → 通义千问 → 硅基流动 → Kimi → 豆包 → 本机 Ollama → 本地检索
（什么都没装时）本地检索
```

| 引擎 | 环境变量（可选·进阶） | 默认模型 | 说明（2026-09 实测本机可达） |
|---|---|---|---|
| DeepSeek | `DEEPSEEK_API_KEY` | `deepseek-chat` | 中文强、便宜 |
| 智谱 GLM | `ZHIPU_API_KEY` | `glm-4-flash` | 有免费档 |
| 通义千问 | `DASHSCOPE_API_KEY` | `qwen-turbo` | 阿里云百炼 |
| 硅基流动 | `SILICONFLOW_API_KEY` | `Qwen/Qwen2.5-7B-Instruct` | 聚合站 |
| Kimi | `MOONSHOT_API_KEY` | `moonshot-v1-8k` | 长文本见长 |
| 豆包 | `ARK_API_KEY` + `XMUHUB_ARK_MODEL` | 需填接入点 ID（`ep-...`） | 火山方舟 |
| 本地 Ollama | **不需要**（自动探测 `127.0.0.1:11434`） | `qwen2.5:3b` | **完全离线、零成本、永久可用** |

引擎状态随时可在界面 AI 面板头部看到（悬停显示完整降级链），也可直接问接口：

```powershell
curl http://127.0.0.1:8765/api/ai
# {"provider":"local","label":"本地检索","chain":["local"],
#  "providers":[{"id":"deepseek","label":"DeepSeek","hasKey":false,"ready":false}, ...]}
```

> 实测记录（`tools/check_ai_settings.py`）：无 Key → `chain=['local']`，问「怎么报销」答出财务处/财务信息化综合平台；
> 填入 Key → 引擎切到该家、`chain=['zhipu','local']`；假 Key → 401 后自动降级到本地并把原因写在回答下方；
> 清除 Key → 回到 `['local']`。`tools/probe_ai_providers.py` 可复查各家接口连通性。

### 有没有"不用 Key、永远免费"的 AI？只有一条路：模型跑在你自己电脑上

**云端不存在"永远免费"**：免费额度是平台的营销手段，随时会改（本项目的默认免费接口
Pollinations 免费档 2026-09 起就改成返回"额度不足"了）。所以能承诺"永久、不用 Key"的，
只有**把模型装在本机**：

1. 安装 [Ollama](https://ollama.com/download)（Windows 一路下一步）
2. 拉一个小模型：`ollama pull qwen2.5:3b`（约 2 GB，一次下载）
3. 打开 AI 面板右上角 **⚙** → 「本机模型」区块会自动检测 → 选模型 → **用这个模型**

之后**断网也能用**：模型在本机跑，不联网、不花钱、不需要 Key。
程序会自动把「本地模型」排进降级链（`ollama → 本地检索`）。

| 方案 | 要 Key 吗 | 花钱吗 | 能承诺"永远"吗 | 说明 |
|---|---|---|---|---|
| **本机 Ollama** | 不要 | 不要 | **能** | 3B 模型在 CPU 上约 5–20 token/s，挑候选这种窄任务够用 |
| 本地检索（内置） | 不要 | 不要 | 能 | 不是大模型，但入口推荐稳定，永远兜底 |
| 智谱 GLM `glm-4-flash` | 要 | 目前免费档 | 不能 | 便宜好用，适合开发期 |
| DeepSeek / 通义 / 硅基流动 / Kimi / 豆包 | 要 | 按量计费 | 不能 | 效果最好，成本极低 |
| ~~公共免密钥接口~~ | 不要 | 不要 | **已被平台取消** | 见上文，已从代码中移除 |

> 用 `tools/fake_ollama_test.py` 可以在没装 Ollama 的机器上验证整条链路
> （起一个假 Ollama，检测 → 切换 → 问答 → 收回）；实测通过：`engine=ollama`。

可选调整：

```bat
setx XMUHUB_AI local             :: 强制离线，不联网
setx XMUHUB_AI zhipu             :: 只用智谱（不降级）
setx XMUHUB_ZHIPU_MODEL glm-4-air :: 换智谱模型
setx XMUHUB_OLLAMA_MODEL qwen2.5:7b :: 换本地模型
```

**体验优化**：免费接口单次约需 10–30 秒，因此面板是**两段式**——
先本地检索**秒出**可点候选，再显示"正在请 AI 精选…"，AI 回答到达后替换；
同一问题会**命中缓存**秒回。

> 隐私提示：API Key 只保存在本机 `data/userdata.json`，不回传前端；使用云端引擎时，你的提问和候选入口清单会发送到该平台；
> 若在意，可用 `setx XMUHUB_AI local` 切到纯本地模式。

**设计要点**

- **零第三方依赖**：只用 Python 标准库（`http.server` + `urllib`），不会出现"demo 现场装包失败"。
- **前端不直连大模型**：API Key 只留在后端进程，前端通过 `/api/ask` 间接调用，Key 不进浏览器。
- **URL 白名单**：`/api/open` 只允许打开目录内已收录的网址，防止被当成任意跳转器。
- **仅监听 127.0.0.1**：服务只在本机回环地址，不对外暴露。
- **窗口形态**：优先用 Edge 的 `--app` 模式（无地址栏/标签页，像原生应用），找不到 Edge 时回退到默认浏览器。

## 已知限制

1. **小程序无法从桌面直接唤起**：微信未提供外部唤起任意小程序的官方能力，因此小程序条目采用"一键复制名称 + 微信搜索"的方式。
2. **云端大模型有延迟**：单次约 2–15 秒，已用"本地秒出候选 + AI 随后精选 + 答案缓存"缓解；介意延迟可切纯本地模式。
3. **云端引擎由第三方提供**：可能限流或临时故障，此时会自动降级到下一家、最终回退本地检索；提问内容会发送到所选平台（可用 `setx XMUHUB_AI local` 完全离线）。
4. **收藏与最近记录是本机的**，换机器不同步（如需同步可接云函数）。
5. **校区标签偏少**：官网只对少数单位明确标注了校区，多数系统是全校通用，因此按校区筛选时以"通用 + 该校区专属"呈现。
6. **端标签按入口形态判定**：网页系统标为电脑端，但多数网页在手机浏览器里也能打开；标"手机端"的表示入口依赖微信/APP。
7. **手机版（静态站）的收藏/身份存在浏览器里**：换浏览器或清缓存就没了；PWA 只有 https 下才能"添加到主屏幕"，iOS 长期不用还可能被系统回收存储。
8. **手机版没有云端 AI**：手机上跑不了几 GB 的本机模型，问答就是浏览器里的本地检索（不联网、不用 Key）。要做更强的 AI 得自建一个中转藏 Key，或让用户自带 Key。
9. **AI 建议仅供参考**：模型只在已收录条目中挑选，不会编造入口；但仍建议以官网为准。
10. 单文件 exe 在部分杀毒软件下会被误报（PyInstaller 常见现象），且本机沙箱内无法完整验证其自解压过程，**建议优先使用绿色版**。
11. **`tools/` 下的脚本依赖仓库外的两份《总集》**：`build_data.py`、`count_urls.py`、`prune_catalog.py`
    需要《厦门大学网址总集.md》《厦门大学微信小程序总集.md》才能工作，而这两份**没有进版本库**。
